# AIris（AI 智瞳）调研报告：自然语言驱动的通用视觉检测与防错平台

> 调研日期：2026-11-22
> 需求来源：工厂组装防错场景（**首个落地场景**）—— 相机实时监控装配工位，引导工人下一步装什么配件、判定安装位置是否正确、全部装完后整检错装/漏装
> 目标形态：**AIris（AI 智瞳）** —— 通用视觉检测与防错引导平台：检测目标、判定规则、工步逻辑全部通过**自然语言 + 配方**表达，适配装配防错、安全监控、缺料提醒、SOP 合规等广泛场景，无需重复开发；Slogan：「一句话，教会 AI 盯现场」
> 部署约束：工厂无网环境，全本地部署
> 命名约定：中文产品名「AI 智瞳」，英文 repo 名「AIris」（AI + Iris/虹膜）；检测引擎可插拔（LocateAnything ↔ Qwen2.5-VL），模型名不进入产品名

## 一、结论速览（TL;DR）

| 维度 | 结论 |
|---|---|
| **模型本身** | LocateAnything-3B（2026-05 发布）能力上**高度匹配**需求：自然语言即指即检、输出归一化坐标框、3B 体量消费级显卡可跑 |
| **最大风险** | ⚠️ **许可证禁止商用**（仅学术/非营利研究），工厂落地前必须解决授权或换模型 |
| **性能** | RTX 5070 Ti（16GB）实测批处理 **61ms/帧（16 FPS）**，单帧约 430ms —— 装配是秒级人工节拍，**性能绰绰有余** |
| **无网部署** | 完全可行：模型 7.7GB 本地加载（支持 `HF_HUB_OFFLINE=1`），无任何云依赖 |
| **成本** | 单工位硬件约 **1.5~2.5 万元**（GPU 工控机 + 工业相机 + 光源 + 引导屏） |
| **可操作性** | 建议 **2~3 周 POC 先行**，重点验证小零件检出率；软件架构按"配方配置化"设计，实现新产品只改配置不改代码 |

**一句话建议**：技术路线成立且性能无压力，但先花一周做 POC 实测工件检出率、同步去谈 NVIDIA 授权或切换 Apache 2.0 模型，这两件事落定之前不要向工厂承诺交付时间。

## 二、LocateAnything-3B 是什么

NVIDIA 于 **2026 年 5 月 26 日**发布的开放词汇检测 / 视觉定位模型（HF：`nvidia/LocateAnything-3B`，模型卡最后更新 2026-06-12）。

### 2.1 基本参数

| 项 | 内容 |
|---|---|
| 总参数量 | 3.83B（BF16 权重约 7.66 GB） |
| 架构 | MoonViT-SO-400M 视觉编码器（MIT 许可）+ Qwen2.5-3B-Instruct 语言模型（Qwen Research 许可）+ MLP 投影层 |
| 核心创新 | **Parallel Box Decoding（PBD）**：并行解码完整边界框而非逐 token 自回归，吞吐提升至 2.5 倍；提供 fast（MTP）/ slow（AR）/ hybrid（默认，MTP 优先、不确定时回退 AR）三档解码模式 |
| 输入 | RGB 图像（最高 2.5K 分辨率）+ 自然语言文本（最长 24K token；训练序列最长 25,600 token） |
| 输出 | 文本形式的结构化坐标 token：`<box> x1, y1, x2, y2 </box>`，坐标为 0~1000 归一化整数；固定长度为 6 的块结构（Semantic / Box / Negative / End） |
| 官方测试硬件 | A100、H100（兼容 Ampere 及以后：RTX 30/40/50、L 系列） |
| 显存峰值 | la_flash 后端 batch_size=4 约 **11.71 GB**（sdpa 后端约 35 GB，需用 flash 后端） |
| 操作系统 | 官方路径仅 **Linux + CUDA + BF16**（不支持 GTX 10 系 / RTX 20 系） |

### 2.2 能力清单

开放词汇检测、密集目标检测、短语指代定位、OCR/文本定位、文档版面分析、GUI 元素定位、点级定位、自动数据标注。官方用例**明确包含工业检测**（Industrial inspection, surveillance, and remote sensing），但未专门提及装配（assembly）场景。

### 2.3 对本项目需求的意义

- **换产品时"要检测什么零件"直接用自然语言写进 prompt**，不需要重新标注、训练 —— 这正是"需求变动只通过自然语言调整"的技术基础
- 输出是归一化坐标框，与预配置 ROI 做几何判定（IoU）非常简单
- 密集检测能力适合"整检多零件齐套"场景

## 三、⚠️ 许可证：最大的坑，先讲清楚

模型卡明确写着：

> *"permits use, reproduction, and modification for academic and non-profit research purposes only. **Commercial use is not permitted, except by NVIDIA and its affiliates.**"*

且底座 **Qwen2.5-3B-Instruct 本身也是 Qwen Research License（非商用）—— 双重非商用**。给工厂做产品直接用存在侵权风险。

### 3.1 三条出路

| 出路 | 说明 | 建议 |
|---|---|---|
| **① 联系 NVIDIA 商业授权** | 模型卡无公开商用条款，需商务洽谈，周期与费用不可控 | 适合大单，POC 阶段不指望 |
| **② 换可商用替代模型（推荐主力方向）** | 见下方对比表 | **架构上做"检测引擎可插拔"**：POC 用 LocateAnything 验证效果上限，产品化切 Apache/MIT 模型 |
| **③ 内部自用论证** | 工厂内部部署（不分发软件）法律灰区更小，但授权条款仍写明禁商用 | 不建议赌，不推荐 |

### 3.2 可商用替代模型对比

| 模型 | 许可证 | 类型 | 开放词汇 grounding | 本地部署成熟度 |
|---|---|---|---|---|
| **Qwen2.5-VL-7B** | Apache 2.0 ✅ | VLM | 强（框+点输出，还能做常识判断：装反/缺失推理） | 成熟（vLLM/LMDeploy） |
| **Grounding DINO 1.0** | Apache 2.0 ✅ | 专用检测 | 强 | 成熟 |
| Florence-2 | MIT ✅ | VLM | 中等 | 成熟 |
| OmDet-Turbo | Apache 2.0 ✅ | 实时开放词汇检测 | 强（主打速度） | 较新 |
| YOLO-World | GPLv3 | 专用检测 | 强 | 成熟（工厂内部不分发可用，卖软件有 GPL 传染风险） |

**推荐组合**：主引擎用 **Qwen2.5-VL-7B**（Apache 2.0；⚠️ 注意其 3B 版同样是 Qwen Research License，别踩）。它除了检测框还能做语义级判断（如螺栓是否拧上、零件是否装反），对装配场景有额外价值；检测精度不够的类目再用小模型微调兜底。

## 四、推理框架选型（本地部署）

| 框架 | 状态 | 实测/特点 | 适配场景 |
|---|---|---|---|
| **locateanything-batch**（社区，MIT） | ✅ 推荐 | RTX 5070 Ti 16GB：**61.3ms/帧 @batch≈32（16.3 FPS）**，单帧约 430ms；batch-15 端到端加速 2.7×（~3.1s → ~1.1s/图）；结果与官方逐位一致（贪心解码 12/12 检查通过）；`pip install locateanything-batch` 即用，支持 `HF_HUB_OFFLINE=1` 离线加载 | 生产主力，吞吐最高 |
| **transformers 原生** | 官方路径 | `AutoModel.from_pretrained("nvidia/LocateAnything-3B", trust_remote_code=True, device_map="auto")`；仅 Linux + CUDA + BF16；`generation_mode="hybrid"` | POC / 功能基线 |
| **locate-anything.cpp（GGUF）** | 兜底 | q8_0 量化 6.3GB（框坐标与 f32 完全一致）、q4_k 4.7GB；**CPU 可跑但 14~22s/图**；支持 CUDA / Metal / Vulkan / **华为昇腾 CANN**（仅 f16）；无 Python 运行时依赖 | 信创/昇腾场景、超低配兜底 |
| **vLLM（社区解耦方案）** | 备选 | 本地 ViT + vLLM 跑 Qwen2 文本部分（`prompt_embeds` API）；吞吐反而最低（1.02 img/s vs batch 版 4.53） | 不推荐，工程复杂收益差 |
| **TensorRT-LLM / NIM** | ❌ 无官方支持 | 生态中未见 | 排除 |

关键优化技术（batch 版）：KV cache 共享（同一图像多查询只做一次视觉编码+prefill）、fast-MTP 多 token 预测、批量视觉编码（block-diagonal varlen 打包，需 flash-attn，可选约 +30% 性能）。

**结论**：GPU 推理用 **locateanything-batch**（或直接 transformers 起步，POC 通过后切 batch 版）。部署形态："Linux 工控机 + 常驻检测服务（FastAPI）+ 上位机/Web UI 调 HTTP 接口"。Windows 习惯的话：服务端跑 WSL2 或 Linux 迷你主机，引导 UI 可继续用 WinForms/WPF（只调接口，不吃模型依赖）。

## 五、硬件配置与成本（三档方案）

价格按 2026 年市场行情**估算**，采购时以实价为准。

### 5.1 计算主机

| 方案 | GPU/整机 | 检测能力 | 硬件成本估算 |
|---|---|---|---|
| **A. POC 验证** | RTX 4060 Ti 16GB 或 5070 Ti 16GB + 普通主机 | 单帧 430ms~1s，单工位够用 | 显卡 ¥4000~7000 + 主机 ¥3000 ≈ **¥8000~10000** |
| **B. 标准生产工位（推荐）** | RTX 5070 Ti 16GB / 4090 + 工控机 | 16 FPS 批处理，多路可扩 | **¥12000~18000** |
| **C. 边缘一体/多工位** | DGX Spark（$3999 ≈ ¥3 万，128GB 统一内存）或 RTX A5000 24GB 工作站 | 多相机并行 | ¥20000~40000 |

> 边缘选型提示：Jetson Orin Nano Super（$249，8GB）跑不动 3B 模型实时检测，别指望；AGX Orin 64GB 理论可行但成本反超 5070 Ti 主机，意义不大。

### 5.2 外围硬件（每工位）

| 件 | 选型要点 | 估算 |
|---|---|---|
| 工业相机 | 固定俯拍，视野=工件×1.3~1.5；500 万像素（2592×1944）黑白足够 —— 装配防错是"定位/有无"级精度（毫米级），不需要高精度测量配置；GigE 口走线长、USB3 便宜 | ¥1500~3000 |
| 镜头 | 定焦 FA 镜头，按工作距离和视野算倍率（正式选型走视觉硬件选型流程精算） | ¥800~2000 |
| 光源 | 金属件反光是主要干扰：**高角度环形光（60~90°）+ 漫射罩**，避免低角度拉长阴影导致边缘位置失真 | ¥1000~3000 |
| 引导屏 + 声光报警 | 工人大屏（当前步骤图示）+ 三色灯 | ¥1000~2000 |
| **单工位合计** | 方案 B 主机 + 外围 | **约 ¥17000~25000** |

## 六、软件架构设计（AIris 平台：通用化是关键）

核心诉求"后续需求变动只用自然语言调整"的落地方案：**把"产品差异"全部收敛到配方文件里**。

```
┌─────────────────────────────────────────────┐
│  引导 UI（WinForms/Web 大屏 + 语音 + 三色灯） │
├─────────────────────────────────────────────┤
│  工步引擎（状态机）                           │
│   步骤N：预期零件X出现在ROI-A、零件Y从ROI-B消失 │
├──────────────────┬──────────────────────────┤
│  规则判定层        │  配方中心（每产品一份配置） │
│  ROI-IoU几何判定   │  · 零件类目=自然语言描述    │
│  数量/顺序/稳定帧  │  · 每步:零件@ROI+判定规则   │
├──────────────────┴──────────────────────────┤
│  检测服务（LocateAnything/Qwen2.5-VL 常驻显存）│
├─────────────────────────────────────────────┤
│  采集层（GigE相机 + 光源控制器）+ 截图存档审计  │
└─────────────────────────────────────────────┘
```

### 6.1 "自然语言调整"的真实边界（需向工厂管理好预期）

- ✅ **改检测目标**：换零件、增减检测类目、改叫法 —— 改 prompt 里的自然语言描述，即改即用，零训练
- ✅ **改装配顺序/数量规则**：改配方 JSON
- ⚠️ **新一个产品上线**：仍需人工做一次"配方编制"（拍照、画 ROI、写零件描述），熟练后约半天 —— 这是"零代码"但不是"零配置"
- ❌ **极小零件（M3 螺丝）、外观相似件、左右对称件装反**：纯开放词汇检测不保证可靠，需要 POC 实测；兜底手段为局部放大视角 / few-shot 微调 / 传统模板匹配双通道

### 6.2 防错判定的可靠性设计（工厂最在意漏检误报）

1. **不依赖单帧**：连续 N 帧（如 3 帧）结果一致才判定，抗工人手部遮挡抖动
2. **位置判定用几何规则**（检测框与预配置 ROI 的 IoU），不用模型"理解"位置 —— 几何判定是确定性的、可审计
3. **关键安全件双通道**：开放词汇检测 + 传统 CV 模板匹配，两者一致才放行
4. **每步自动截图存档**，形成质量追溯链（客诉举证刚需）

## 七、主要风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| **许可证禁商用** | 🔴 高 | 产品化切 Apache 2.0 模型（Qwen2.5-VL-7B 主力）；POC 可先用 LocateAnything 摸效果上限 |
| 小零件/相似件检出率未知 | 🟡 中 | POC 第一件事：拿真实工件实测 10 类典型零件（大件、小螺丝、反光件、相似件）；必要时分区拍摄/微调兜底 |
| 金属反光误检 | 🟡 中 | 光源设计（漫射罩）+ 相机偏振片 |
| 官方仅 Linux + BF16 | 🟢 低 | 服务端用 Linux/WSL2，显卡 RTX 30 系以上 |
| 模型无显式置信度输出 | 🟢 低 | 用多帧稳定性 + 几何规则补偿 |

## 八、落地路径建议

| 阶段 | 周期 | 内容 |
|---|---|---|
| **POC** | 第 1 周 | POC 环境搭建（5070 Ti + transformers 原生推理），拿工厂真实工件照片跑检出率测试 —— **这一步直接决定整个技术路线是否成立** |
| **POC** | 第 2~3 周 | 单产品配方串全流程（工步引导 + ROI 判定 + 整检），UI 用最简 Web 页 |
| **MVP** | 1.5~2 个月 | 接入真相机流、引导大屏、声光报警、截图审计 |
| **平台化** | 3~4 个月 | 配方中心、多工位、MES 对接、模型可插拔（LocateAnything ↔ Qwen2.5-VL 切换开关） |
